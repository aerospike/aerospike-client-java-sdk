# AEL v2 — resolved design decisions

This file records **normative rules** for Aerospike Expression Language (AEL) v2. When anything elsewhere in `docs/ael-v2/` appears to disagree, **this file wins**. Source precedence for this folder is described in [SOURCES.md](SOURCES.md).

| Topic | Normative v2 rule | Non-normative patterns |
|-------|-------------------|---------------------|
| **Range separator inside `{}` / `[]` selectors** | **`:`** is the **range** delimiter **inside** map/list selector brackets. **`..` is not used inside selectors**; it is **reserved** for a future **recursive-descent** path operator (JSONPath-style). Examples: `{@a:d}`, `[1:5]`, `{=x:y}`, `{#0:3}`. | Hyphen **`{a-d}`** key ranges inside `{…}`; **`{a..c}`** inside selectors where **`:`** is the range delimiter; **`..`** inside brackets next to **`:`** for ranges. |
| **Explicit map-key dimension in selectors** | Inside `{…}`, the **key** dimension uses **`@`**: `{@a}` singular key, `{@a:d}` key range, `{@a,b,c}` key list. A **bare identifier** as a path segment still navigates by map key; **`@` inside `{…}`** is the explicit selector form. | Comma lists in `{…}` for keys **without** **`@`**. |
| **List / value / rank dimensions** | First character after `{` or `[` sets the dimension: **none** = index, **`@`** = map key (in `{…}` only), **`=`** = value, **`#`** = rank. Tables: [path-and-selectors.md](path-and-selectors.md). | Selector examples that omit the dimension prefix (`@`, `=`, `#`, …). |
| **Comma, tilde, bang** | **`,`** = list; **`~`** = relative-to binding; **`!` immediately after `{`/`[`** = inverted selection (including `{!#…}` forms). | Punctuation in selectors outside these rules. |
| **Language constants (`NIL`, `INF`, wildcard `*` in literals)** | **UPPERCASE** for `NIL`, `INF`, and the wildcard **value** `*` inside list/map **literals**. Do not use lowercase `nil` for the CDT sentinel. | Lowercase **`nil`** for the CDT sentinel. |
| **Reserved words** | **`and`**, **`or`**, **`let`**, **`when`**, **`then`**, **`default`**, **`true`**, **`false`**, and other keywords are **lowercase** in source. | Uppercase keyword spellings (`AND`, `WHEN`, …). |
| **Path type suffix / loose typing** | **`$.bin:T`** — strict static type; participates in canonical bin typing for inference/codegen. **`$.bin:local:T`** — loose / per-branch; does not participate in canonical propagation. Examples: `$.bin:LIST.*…`, `$.bin:MAP.{…}`, `when` branches with `$.data:local:INT` vs `$.data:local:FLOAT`. | Long-form **`$.local(name, type: T)`** instead of **`$.bin:T`** / **`$.bin:local:T`**. |
| **Loop-variable type suffix** | In path filters and **`.modify()`** bodies, **`@:T`** types the current element **`@`** (same type names as path suffixes: `INT`, `FLOAT`, `STRING`, …). For a field of **`@`**, attach the suffix to that navigation: **`@.price:FLOAT`**. | **`@.get(type: T)`** or **`expr.get(type: T)`** as a cast, or **method-style** **`path.get(…, type: T, …)`** instead of **selector + `:T`** (**`$.a.[0]:T`**, **`$.m.k:T`**, …). |
| **Whole-map / whole-list typing** | Treat a bin or path value as a **map** or **list** with **`$.path:MAP`** or **`$.path:LIST`** (e.g. equality to a map/list literal, or inference). **Do not** use empty **`$.path.{}`** or **`$.path.[]`** as pseudo-selectors for typing. | **`$.mapBin.{}`**, **`$.listBin.[]`** as casts. |
| **`count()` without `{}` / `[]`** | **`count()`** on a path whose value is a **single** LIST or MAP bin (or nested path typed as such) does **not** require **`{}`** / **`[]`** to disambiguate list vs map; compilation uses a **CDT count**–class lowering in the `Exp` tree ([open-issues.md](open-issues.md) §4). Use **`$.bin.count()`**, not **`$.bin.{}.count()`** / **`$.bin.[].count()`** for that purpose. | **`{}.count()`** / **`[].count()`** used only to force map vs list typing. |
| **Explicit typing on builtins, record helpers, and CDT paths** | **(1)** Builtins **with** arguments: **`name:T(args)`**. **(2)** **No-arg** record helpers: optional **`():T`** after **`()`** (e.g. **`$.key():INT`**); omit **`:T`** when inference suffices (**`$.key() == 'Bob'`**). **(3)** **List/map reads:** put **`:T`** on the path tail after the selector that yields the value — **`$.l.[0]:INT`**, **`$.m.k:STRING`** — and **`$.bin:T`** on a bin root when needed ([path-and-selectors.md](path-and-selectors.md)). | **`name(args):T`** where **`name:T(args)`** is preferred; **`$.key(type: T)`** inside **`()`**; AEL shaped like **`path.get(index:, type:, …)`** or **`path.getByKey(key:, type:, …)`** instead of **selector + `:T`**. |
| **`.select(return: …)` vs explicit getters** | **Read surface:** **implicit get** (default) for ordinary value reads; **`getKeys()`**, **`getKeyValues()`**, **`getTree()`** when the result shape is not “values only”. **`getValues()`** is defined for explicit spelling but is **redundant** with implicit get—**prefer omitting it** unless it helps readers or tooling. Optional **`.select(...)`** may appear where tooling emits it; closure is tracked in [open-issues.md](open-issues.md) §3. | A read surface limited to **`.select(return: …)`** without getter terminals. |
| **`count()` semantics** | **Single-select-only** navigation ending at a LIST/MAP uses **element-count / size** semantics (dedicated size path in the CDT model). **Any multi-select** segment uses **match-count** semantics (`RESULT_TYPE_COUNT` class). Do not overload one spelling to mean both without making single vs multi select obvious from the path. | One **`count()`** spelling overloaded for size, existence-class counts, and multi-select match counts with no syntactic distinction. |
| **`getKey()` vs `getKeys()` naming** | Exposed names **`getKeys()`**, **`getValues()`**; plural even when a single key/value is returned. | Singular **`getKey()`** as the only exposed name. |
| **Nested sub-expressions in filters** | **Disallowed:** no sub-expression nested inside another sub-expression’s filter/path argument. | Nested filters with unbounded depth. |
| **Key-list + subsequent filter (“and then”)** | **Semantics:** choose a **key list** (or equivalent key-set selector), **then** apply a **predicate** **at that map level** on the restricted entries (not “iterate all children” — that is **`.*[?( … )]`**; see [open-issues.md](open-issues.md) §1). Distinct from a bare key-list read with no predicate. The **ASCII punctuator** between key-list and filter (e.g. `&`) is not fully standardized — [open-issues.md](open-issues.md). | Treating key-list + filter as **`.*[?( … )]`** child iteration, or assuming one punctuator without checking [open-issues.md](open-issues.md). |
| **Rank / multi-select result ordering** | For **list** rank-range style results, **do not assume** stable ordering unless the operation definition guarantees it. **Map** rank-range behavior may differ. Default mental model: **unordered** unless explicitly documented for the op. | Assuming sorted rank output in all cases. |
| **Flag properties on path operations** | Compact **flags** (e.g. `NO_FAIL`) use a **`:` flag** convention on flag-heavy ops; data arguments still use normal parameters. **Placement** (before vs after `()`) is **open** — [open-issues.md](open-issues.md). | N/A |
| **Path terminals vs `.get({selector})` / `.remove({selector})` bridge** | **Terminals (default model):** after **`$.…`** path navigation, reads end with **implicit get** (values), **`getKeys()`**, **`getValues()`**, **`getKeyValues()`**, **`getTree()`**, **`count()`**, **`exists()`**, …; **`remove()`**, **`modify()`**, … end removes/writes. Those calls are **path terminals** — in the usual case they take **no selector argument** because selectors already appear on the path. **Bridge (also normative author syntax):** **`path.get({selector})`** / **`path.remove({selector})`** — a **selector** in **parentheses** supplies extra navigation for that call; **`.get`** returns a **list**. Inner selectors use the same **`:`** range rules as on the path. **Codegen:** a compiler **may** lower some shapes as “path + no-arg terminal” and others via the bridge depending on **`MapExp` / `ListExp`** / CTX wiring for that SDK — that choice is **implementation**, not a second read model ([list-map-functions.md](list-map-functions.md)). | **`{x..y}`** inside selectors (non-`:` range delimiter). |
